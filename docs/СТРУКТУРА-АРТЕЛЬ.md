## 1. НАШИ ДОГОВОРЕННОСТИ

### 1.1 Основной принцип разработки

**ДОГОВОРЕННОСТЬ:**
```
Каждый патч проходит через СТРУКТУРУ-АРТЕЛЬ

Разработчик → Проверяет соответствие СТРУКТУРЕ → Если НЕ соответствует:
  ОСТАНАВЛИВАЕТСЯ → Обсуждает изменение СТРУКТУРЫ → Обновляет СТРУКТУРУ
  → Затем разрабатывает патч согласно новой СТРУКТУРЕ

Если СООТВЕТСТВУЕТ:
  → Разрабатывает согласно СТРУКТУРЕ
  → Тестирует в реальном приложении
  → Создает коммит и патч-описание
  → Всё!
```

### 2.3 Как данные текут через приложение

```
1. ЗАГРУЗКА (startup)
   ├── Electron создает window
   ├── Загружается index.html
   ├── Запускается app.js
   ├── init() функция загружает данные через IPC
   ├── window.api.getData() → main.js:ipcMain.handle('api:getData')
   ├── Читается artel.json
   └── Данные заполняют appState

2. ВКЛАДКИ (navigation)
   ├── Пользователь выбирает вкладку (Dashboard, Файлы и т.д.)
   ├── switchTab() скрывает/показывает разделы
   ├── loadDashboard() заполняет страницу данными из appState
   └── Всё отображается на экране

3. ИЗМЕНЕНИЯ (editing)
   ├── Пользователь изменяет файл или категорию
   ├── app.js отправляет изменение через IPC
   ├── main.js обрабатывает и сохраняет в artel.json
   ├── appState обновляется
   └── Интерфейс обновляется

4. СОХРАНЕНИЕ
   ├── artel.json автоматически сохраняется после изменений
   ├── Резервная копия создается в backups/
   └── Google Drive синхронизация (если настроена)
```

**Статус:**
- [x] Поток данных определен
- [x] IPC коммуникация работает
- [ ] Требует тестирования

---

### 3.2 ❌ КАТЕГОРИЧЕСКИ НЕЛЬЗЯ

| Что | Почему | Исключение |
|-----|--------|-----------|
| Hardcode пути типа `C:\Users\...` | Портативность | Никогда |
| require() в renderer процессе | Безопасность | Только preload.js |
| Синхронные файловые операции | Производительность | Только при старте |
| Хранить пароли в коде | Безопасность | Только в .env локально |
| Смешивать данные с кодом в GitHub | Организация | Никогда |
| Доверять входным данным | Безопасность | Всегда валидировать |
| Комментировать очевидный код | Чистота | Комментировать только NON-OBVIOUS |

## 4. ИСТОРИЯ РЕШЕНИЙ

### 4.1 Проблема #1: Приложение зависало при загрузке Dashboard

**Дата обнаружения:** 2026-10-11  
**Статус:** ✅ РЕШЕНО

**Что было:**
```
Dashboard отображался ДО загрузки данных
  ↓
loadDashboard() пытался доступиться к пустому appState.projects
  ↓
JavaScript ошибка
  ↓
Приложение зависает
```

**Как решили:**
```
1. Скрыли Dashboard по умолчанию (display: none)
2. init() функция загружает данные
3. После загрузки → switchTab('dashboard')
4. Тогда loadDashboard() уже имеет готовые данные
```

**Результат:**
- [x] Dashboard загружается правильно
- [x] Нет зависаний
- [x] Данные отображаются корректно

### 4.2 Проблема #2: Неправильные имена полей в loadDashboard()

**Дата обнаружения:** 2026-10-11  
**Статус:** ✅ РЕШЕНО

**Что было:**
```
Использовал:
  - appState.files (не существует, нужно allFiles или fileCount)
  - p.id (не существует, нужно p.name)
  - p.projectId (неправильно, нужно p.name)
```

**Как решили:**
```
Исправил на правильные поля:
  - (p.fileCount || 0) вместо appState.files.filter()
  - selectProject('${p.name}') вместо selectProject('${p.id}')
  - Добавил проверку appState.projects && appState.projects.length
```

**Результат:**
- [x] Dashboard отображает проекты
- [x] Клик на проект работает
- [x] Нет ошибок в консоли

**Статус:** ❓ ОТКРЫТО  
**Приоритет:** 🟡 СРЕДНИЙ

**Аргументы ЗА:**
- Быстрее при работе с большими файлами

- JSON портабельнее и проще для понимания
- Нет дополнительных зависимостей

**Решение:** Пока оставляем JSON, но в v0.9 можем переделать
