## 1. АРХИТЕКТУРА ПРИЛОЖЕНИЯ

### 1.1 Стек технологий
- **Desktop:** Electron 13+ (Node.js + Chromium)
- **Frontend:** Vanilla JavaScript (SPA - Single Page Application)
- **Backend:** Node.js в Electron main process
- **Database:** JSON файл (artel.json)
- **Дизайн:** CSS3 с переменными (light/dark theme)

### 1.2 Компоненты приложения

```
АРТЕЛЬ (Electron App)
├── main.js (Electron main process)
│   ├── IPC обработчики для API
│   ├── Работа с файловой системой
│   ├── Telegram Bot интеграция
│   └── Синхронизация с Google Drive
├── preload.js (Безопасный контекст IPC)
├── public/ (Frontend)
│   ├── index.html (главная страница)
│   ├── app.js (основная логика приложения)
│   ├── styles.css (стили)
│   ├── pages/
│   │   ├── dashboard.html
│   │   ├── about.html
│   │   └── ... (другие страницы)
│   └── components/ (переиспользуемые компоненты)
├── data/
│   ├── artel.json (основная БД)
│   └── backups/ (автоматические резервные копии)
└── config.json (конфигурация приложения)
```

### 1.3 Архитектурные принципы

✅ **ОБЯЗАТЕЛЬНО:**
- [ ] Разделение ответственности (MVC паттерн)
- [ ] Безопасный IPC между процессами
- [ ] Портативные относительные пути
- [ ] Асинхронная загрузка данных
- [ ] Обработка ошибок на всех уровнях
- [ ] Логирование всех операций

❌ **ЗАПРЕЩЕНО:**
- [ ] Прямой доступ к файловой системе из frontend
- [ ] Node.js require() в renderer процессе
- [ ] Синхронные операции чтения больших файлов
- [ ] Hardcoded абсолютные пути
- [ ] Доверие неопределённым данным от пользователя

## 2. СИНХРОНИЗАЦИЯ ДАННЫХ

### 2.1 GitHub (КОД)
**Что хранится:**
- `main.js`, `preload.js`
- `public/` (все файлы приложения)
- `PATCHES.md`, `docs/`
- `.gitignore`

**Правило:** Только исходный код. Никаких данных!

### 2.2 Google Drive / Локальный диск F: (ДАННЫЕ)
**Что хранится:**
- `Проекты/` (все файлы пользователя)
- `photos/` (изображения для Telegram)
- `backups/` (резервные копии БД)
- `config.json` (локальная конфигурация)

**Правило:** Только данные. Никакого кода!

### 2.3 .gitignore (ОХРАНА)
```
# ДАННЫЕ - НИКОГДА НА GITHUB
Проекты/
photos/
backups/
config.json
*.local.json

# NODE MODULES
node_modules/
package-lock.json

# КЭШИРОВАНИЕ
cache/
.DS_Store
```

## 3. СТРУКТУРА ФАЙЛОВ

### 3.1 Формат artel.json

```json
{
  "projects": {
    "PROJECT_NAME": {
      "id": "project-id",
      "name": "PROJECT_NAME",
      "path": "Проекты\\PROJECT_NAME",
      "fileCount": 100
    }
  },
  "files": [
    {
      "id": "PROJECT__filename.ext",
      "project": "PROJECT_NAME",
      "name": "filename.ext",
      "path": "filename.ext",
      "fullPath": "Проекты\\PROJECT_NAME\\filename.ext",
      "category": "category-id",
      "thumbnail": { "status": "indexed" }
    }
  ],
  "categories": [
    {
      "id": "cat-0",
      "name": "Категория",
      "color": "#1688FF",
      "icon": "🏷️"
    }
  ]
}
```

### 3.2 Структура appState (Frontend)

```javascript
let appState = {
  currentProject: null,        // текущий выбранный проект
  projects: [],               // массив проектов
  categories: [],             // массив категорий
  allFiles: [],              // все файлы текущего проекта
  orders: [],                // заказы из Telegram
  selectedProjectFiles: Set(), // выбранные файлы
  viewMode: 'table',         // 'table' или 'gallery'
  iconSize: 120              // размер иконок
};
```

## 4. СТАНДАРТЫ РАЗРАБОТКИ

### 4.1 Код

✅ **ОБЯЗАТЕЛЬНО:**
- [ ] Комментарии только для NON-OBVIOUS логики
- [ ] Функции максимум 50 строк
- [ ] Проверка на undefined/null перед доступом к свойствам
- [ ] try-catch для асинхронных операций
- [ ] console.log для отладки, log() для production

❌ **ЗАПРЕЩЕНО:**
- [ ] var (только let/const)
- [ ] eval()
- [ ] Глобальные переменные (кроме appState)
- [ ] Обработчики с более чем 3 параметрами

### 4.2 Коммиты Git

**Формат сообщения:**
```

Подробное описание что изменилось.
- Пункт 1
- Пункт 2

Co-Authored-By: Claude Haiku 4.5 <noreply@anthropic.com>
```

**Правило:** 1 логическая изменение = 1 коммит

### 4.3 Именование

| Тип | Стиль | Пример |
|-----|-------|--------|
| Переменные | camelCase | `currentProject`, `fileCount` |
| Константы | UPPER_SNAKE_CASE | `DB_FILE`, `CACHE_PATH` |

## 5. ПРАВИЛА ВЕРСИОНИРОВАНИЯ

### 5.1 Формат версии

`v0.MAJOR.MINOR`

- **0** = Pre-release статус (не 1.0 пока)
- **MAJOR** = Крупные изменения архитектуры (редко)
- **MINOR** = Новые функции или исправления (часто)

Примеры:
- v0.1.0 → Первый релиз
- v0.5.3 → 5-й major релиз, 3-й минор патч
- v0.7.1 → Текущая версия

## 6. ЗАПРЕТЫ И ОГРАНИЧЕНИЯ

### 6.1 ❌ ЗАПРЕЩЕНО ДЕЛАТЬ

| Что | Почему | Исключение |
|-----|--------|-----------|
| Хранить пароли в коде | Безопасность | Только в .env локально |
| Hardcode пути | Портативность | Использовать ROOT_PATH |
| require() в frontend | Безопасность | Только в main.js |
| Синхронные файловые операции | Производительность | Только при старте приложения |
| Смешивать данные и код в GitHub | Организация | Строго разделять |
| Очень большие объекты в памяти | Производительность | Использовать pagination |
| Доверять input без валидации | Безопасность | Всегда валидировать |

### 6.2 ✅ ВСЕГДА ПРОВЕРЯТЬ

```javascript
// ❌ ПЛОХО
const name = project.name.toUpperCase();

// ✅ ХОРОШО
const name = project?.name?.toUpperCase() || 'UNKNOWN';
```

```javascript
// ❌ ПЛОХО
async function loadData() {
  const data = await api.getData();
  process.data = data;
}

// ✅ ХОРОШО
async function loadData() {
  try {
    const data = await api.getData();
    appState.projects = data.projects || [];
  } catch (err) {
    console.error('LoadData error:', err);
  }
}
```
