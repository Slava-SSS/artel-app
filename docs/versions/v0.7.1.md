## 📝 КАК ИСПОЛЬЗОВАТЬ СТРУКТУРУ-АРТЕЛЬ

### Сценарий 1: Планируете новый патч
```
1. Откройте СТРУКТУРА-АРТЕЛЬ.md (в приложении или на GitHub)
2. Прочитайте релевантные разделы (архитектура, стандарты)
3. Проверьте что ваши изменения не нарушают ЗАПРЕТЫ
4. Планируйте работу согласно РЕГЛАМЕНТУ
5. Разрабатывайте с учетом правил
```

### Сценарий 2: Хотите изменить СТРУКТУРУ
```
1. Откройте вкладку "О проекте"
2. Нажмите "✏️ Редактировать"
3. Внесите изменения в Markdown редактор
4. Нажмите "💾 Сохранить"
5. Обновится docs/СТРУКТУРА-АРТЕЛЬ.md
6. Создайте коммит с объяснением почему изменилась СТРУКТУРА
```

### Сценарий 3: Завершили успешный патч
```
1. Коммитьте в GitHub
2. Откройте вкладку "О проекте"
3. Обновите История.md с описанием нового патча
4. Создайте vX.X.md файл в docs/versions/
5. Обновите дату в СТРУКТУРЕ-АРТЕЛЬ.md
```

## 🎓 ОБУЧАЮЩИЙ МАТЕРИАЛ

### Как СТРУКТУРА-АРТЕЛЬ помогает разработке?

**Проблема:**
- Без регламента каждый разработчик делает по-своему
- Быстро накапливаются технический долг и противоречия
- Трудно объяснить Claude правила если их нет в документах

**Решение:**
- СТРУКТУРА-АРТЕЛЬ = общий регламент
- Все знают что можно и что нельзя
- Claude может проверять себя по СТРУКТУРЕ
- История изменений сохраняется для будущих разработчиков

### Почему это "конструктор обратной связи"?

Разработчик ← → Claude общаются через:
1. **Комментарии в СТРУКТУРЕ** — вопросы и идеи
2. **История.md** — решения и их обоснование
3. **vX.X.md описания** — что изменилось и почему
4. **Чек-листы** — что проверить перед патчем
